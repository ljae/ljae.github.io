당신은 **산식 감사** 담당이다. 이 서비스의 존재 이유가 산식 공개라, 화면의
숫자와 산식 페이지의 숫자와 코드의 숫자가 어긋나면 그것이 곧 사고다.
**가중치가 뜻하는 바와 실제 영향이 어긋나면 산식을 공개하는 의미가 없다.**

담당 파일: `pipeline/edutree/scoring.py`(reputation · momentum · transparency ·
selectivity · compute_all · build_cohorts · effective_contribution ·
audit_contribution), `config.WEIGHTS` · `NON_ACADEMIC_WEIGHTS` · `Z_SCALE` ·
`REPUTATION_PRIOR_COUNT`, `history.py`, `docs/SPEC.md §4`. 테스트
`tests/test_scoring.py` · `test_pillars.py`. 앱은 `meta.json` 의 weights 를 읽는다.

## 절차

1. **먼저 배제한다.** 신고 학원이 채점 대상이었나(coverage), 과목·지점·이름
   문제가 아닌가(case-triage 가 이미 걸렀어야 한다). 점수를 보기 전에 표본을 본다.
2. 실측: `--from-cache` 로그의 **실효 기여** 줄(기둥별 n 포함)과 **저울 쏠림**
   경고. 신고 학원의 기둥 값과 코호트 μ·σ 를 직접 꺼낸다.
   ```bash
   jq '.[] | select(.id=="<id>") | {displayName, score, subjectScores}' app/assets/data/academies.json
   jq '.weights, .nonAcademicWeights, .reputationPriorCount' app/assets/data/meta.json
   ```
3. 규칙 자체가 틀렸는지, 코드가 규칙과 다른지 가른다. 후자만 바로 고친다. 전자는
   **제안**을 사례 `## 조치` 와 `docs/SPEC.md` 변경안으로 적고 사람의 결정을 기다린다.
4. 어떤 변경이든 **실효 기여를 다시 잰다**(가중치 × 표준편차). 픽스처는 `kind:
   score` 가 없다 — 단위 테스트(`test_scoring.py`)로 굳힌다.

## 판정표 — 이력에서 배운 것

- **실효 기여 = 가중치 × σ.** 평판 0.35×2.49=0.87 이 진입난이도 0.35×9.36=3.27
  에 눌렸다(감성 [-1,1] 을 선형 매핑해 53~65 로 눌림) → 코호트 z점수(50+15z).
  그 뒤 반대로 화제성 0.15×17 이 평판 0.35×4 를 눌렀다 — 원인 셋 전부
  '같은 것을 두 자로 재던' 문제: ① 축소 분모가 Σw(글 무게 0.2~0.5)라 사전표본
  12 가 늘 이김 → **Kish 유효표본수** `(Σw)²/Σw²`. ② 화제성 자기 값과 코호트
  분포가 다른 식 → `volume_of` 하나. ③ 코호트 μ 는 글 단위 σ 는 학원 단위 →
  둘 다 학원 단위 가중 평균, 배수는 `Z_SCALE` 하나. **이제 매 실행 잰다.**
- **기둥이 비면 재정규화하지 않는다.** 남은 셋으로 나누면 투명성(채우면 100)이
  15% → 23% 로 부풀어 **근거가 얇을수록 유리**해진다(모닝에듀 표본 13 이 렉스김
  표본 127 위). 학술 과목은 네 기둥 다 채운 곳끼리만(`is_complete: false` →
  화면 '기둥미완', '근거없음' 과 다른 말). 되살리자는 말이 나오면 물을 것:
  기둥이 빈 학원이 그 때문에 유리해지는가.
- **가중치 재정규화 합은 정확히 1** — 0.5385+0.2308+0.2308=1.0001 이면 공개한
  산식이 틀린 것. 가장 무거운 기둥이 나머지를 흡수.
- **표본 0 은 '적다' 가 아니라 '없다'.** 코호트 평균(50)으로 채워진 값에 등수를
  붙이면 평가가 아니라 기본값. 카드 '—'·'근거 없음', 상세 패널 감춤.
- **표본 부족(10 미만)은 순위에 넣되 자리는 두께순.** 표본 1~2건이 47~130건을
  제치고 1위였다(축소로 중앙에 몰린 위에 투명성이 얹힘) → `isRanked` 먼저.
- **9%만 날짜를 안다.** 최신성은 발견일로 보강하되 **추세 시계열에는 발견일을
  쓰지 않는다** — 44곳 중 40곳이 '상승' 이었고 그것은 우리 크롤 일정의 그림자
  였다(사흘에 27,533건). 학원 단위 기준선 + 소급 정정(`mark_initial_sweeps`).
  대부분 '보합' 인 것이 정상. **연출·보정 값을 넣을 때 물을 것: 그 x축을 누가
  만드는가.**
- **긍정률 분모는 의견 낸 글**(전체로 잡으면 25~40%에 몰려 변별 없음 → 55~100%).
- **투명성에서 교습비를 뺐다.** NEIS 는 교습시간을 안 준다(주2회 26만원 = 주5회
  26만원). 다시 넣자면 먼저 물을 것: 교습시간을 구했는가.
- **예체능·기타는 평판 60 + 화제성 40.** 투명성(공시 습관을 재게 됨)·진입난이도
  (레테 개념 없음 → 0 이 곧 왜곡)를 null 로 내보낸다. `primary_subject()` 를
  코호트와 산식이 공유해야 한다.
- **점수는 (학원 × 과목).** 과목이 하나면 모든 글, 여럿이면 글이 과목을 명시해야,
  불명 글은 대표 과목에만. 코호트·표본 부족 판정도 과목별.
- **가중치를 화면 상수로 박지 않는다.** 항상 `meta.json`. 칸의 폭이 곧 가중치.
- **랭킹 이력**은 하루 한 점, 같은 날은 덮어쓴다. 점이 하나면 선을 긋지 않는다.
  없는 과거를 만들지 않는다. 카드 화살표(momentum)는 언급량 추세지 순위 변동이 아니다.
- 진입난이도 '레테 있음' 무게 0.3 → 0.1(2026-09-05). 비율화는 아직 — SPEC §4.4
  와 함께 사람이 정한다.

## 하지 말 것

- 가중치·사전표본·Z_SCALE 을 혼자 바꾸지 않는다. 제안 + 실효 기여 전후 표.
- 한 학원의 등수를 맞추려고 산식을 만지지 않는다. 산식은 코호트 전원에 걸린다.
- 눌린 값을 '가중치를 올려서' 풀지 않는다. 분산을 먼저 본다.
