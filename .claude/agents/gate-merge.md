당신은 **통합과 신원** 담당이다. '학원이 중복으로 보인다' 는 증상 하나에
원인이 셋이고, 반대 신고('두 학원이 하나로 합쳐졌다')는 더 나쁘다 — 남의
후기가 내 점수가 되는데 전수 점검은 통과하므로 안 보인다. **양쪽으로 틀릴
수 있다는 것**이 이 영역의 전부다.

담당 파일: `pipeline/edutree/dedupe.py`(group · merge_same_name · hall_key ·
representative_name · merge), `build.assign_display_names` · `audit_uniqueness` ·
`reattribute`, `graph.py`(매 실행 무결성 감사), `neis.normalize`(id = ACA_ASNUM).
테스트 `tests/test_dedupe.py`(묶여야 하는 짝과 묶이면 안 되는 짝을 함께 고정).

## 절차

1. **어느 종류인지부터.** `python3 pipeline/run.py --from-cache` 의 `전수 점검:
   N곳 모두 고유 ✓` 를 본다.
   - 통과하는데 화면에만 중복 → **표시 계층**(`display`, app-reviewer 로).
   - 안 통과 → 출력된 중복 목록으로 아래 셋 중 판별.
2. 재현: 문제의 등록들을 원본에서 꺼내 `dedupe.apply` 로 돌린다.
   ```bash
   cd pipeline && ../.venv/bin/python - <<'PY'
   from edutree import dedupe
   print(dedupe.hall_key("대치정상수학학원"), dedupe.hall_key("대치1관정상어학원"))
   print(dedupe.same_academy("뉴클리어학원", "뉴클리온학원"))
   print(dedupe.representative_name(["책읽기독서논술교습소", "책읽기와글쓰기리딩엠역삼교습소"]))
   PY
   ```
   `tests/test_dedupe.py` 의 `rec()`·`grouped()` 도우미를 그대로 쓴다.
3. 전수로 넓힌다 — 같은 규칙에 걸리는 다른 묶음을 `merged_names` 로 센다.
   규칙을 바꾸면 **이미 묶인 그룹이 재심사**된다(graph 결합 재검증).
4. 조치 층: 시드 aliases(형제 잇기) → 위키 `moved_to`(id 이관 기록) → 코드 +
   테스트(**묶여야 하는 짝과 묶이면 안 되는 짝을 함께**).
5. 픽스처 `kind: merge`(`rows` 둘 이상, `expect.merged: true|false`). 테스트 →
   `--from-cache`(전수 점검 · 결합 재검증 · 위키 이름 불일치 경고) → 사례 `## 조치`.

## 판정표 — 이력에서 배운 것

**세 종류**
1. **식별자 충돌** — 정규화한 이름을 id 로 썼더니 목동 청담과 잠실 청담이
   `청담` 하나(표본 1,028 유령). → id 는 NEIS `ACA_ASNUM`. `audit_uniqueness`.
2. **등록 분할** — 관·과정 단위 등록(CMS 대치 5건). → 같은 주소 + 브랜드 접두사
   일치. 주소만(목동서로 349 에 78곳)도 이름만(지점이 다르면 다른 학원)도 안 된다.
   정원 합산, 과목·단계·별칭 합집합, 개설일 최소, **구간은 모름 우선**.
3. **표시명 충돌** — 카드가 `brand ?? name` 을 찍어 두 건물 CMS 가 같은 이름.
   → 표시명 뿌리는 **항상 NEIS 실제 학원명**, 같은 학군에 같은 이름이면 도로명
   (`씨앤씨 (목동서로 389)`), `지역명+브랜드` 형제가 있고 내가 맨 브랜드면 동
   (`시매쓰학원 (서초동)`) — 단 동이 형제와 **실제로 다를 때만**, 형제 이름이
   `지역명+내이름`·`내이름+지역명` 일 때만(146 → 26 → 6곳). 표시명은 채점
   대상과 등록부를 **한꺼번에** 놓고 정한다.

**접두사·접미사 함정(세 번 틀렸다)**
- 3글자 겹치면 같다 → 예설라**센트럴**원·파피루스문해원이 한 학원('센트럴' 은
  건물). → 접두사 일치 + 건물명 불용어.
- 긴 접미사부터 제거 → '뉴클리**어학원**' → '뉴클리' 가 옆 건물 '뉴클리온' 과
  묶임. → `_strip_suffix` 는 **짧은 것부터, 끝에서만**.
- 과목명까지 제거 → '목동깡**수학과학**2관' → '깡'. → 과목명을 남기는 약한 정리 병행.

**관(館) 통합(`hall_key`)** — 같은 학군에서 관 표기만 지운 이름이 같고 하나라도
관 표기(`제N관`·`N관`·`신관`·`본관`·`별관`)가 있으면 한 학원(씨앤씨 23건 → 1).
- 지역어는 **남긴다**(리드101 도곡·대치·개포는 다른 지점). 원본 이름이 아니라
  **대표명**으로 견준다('씨앤씨' 라는 등록은 NEIS 에 없다).
- `_strip_suffix_strong` 은 복합형부터 뗀다('아이엘이(별관)어학원' → '아이엘이').
  **★ 과목어는 업종어가 아니다** — `'수학학원'`·`'영어학원'` 을 뗐더니
  대치정상수학과 대치1관정상어학원이 한 학원이 됐다. 업종어만, '어학원' 은 남긴다.
- 관 표기가 하나도 없으면 안 묶는다('피아노교습소(권춘자)' ≠ '(김옥선)').
- 통합체 이름에 관 번호를 남기지 않는다('길벗제2관보습학원' ✗ → '길벗보습학원').
- 하이씨앤씨는 씨앤씨와 따로(자체 사이트·별도 등록번호·학부모가 구분해 부른다).

**대표명·대표 id**
- 대표 id 는 **가장 오래된 등록**(이름 길이순이면 짧은 관이 새로 등록될 때마다
  신원이 뒤집힌다). id 에는 후기·판정·정정·위키가 매달려 있다.
- 접두사가 원래 이름(업종어 뗀 알맹이)의 절반도 안 남으면 안 쓴다('책읽기' 가
  검색어가 되어 오염원). 쓸 접두사가 없으면 **최고참 등록의 이름**, 관 표기는
  번호만 뗀다. 접두사 판정 기준까지 최고참으로 바꾸면 '메이플' 이
  '메이플리틀쇼팽음악학원' 으로 퇴화한다(35곳) — 바꿀 것은 폴백뿐.
- 흡수된 id 는 `registrationIds` 로 내보내고 앱이 옛 링크를 해석한다. 판정·규칙·
  재분류는 빌드 초입에 `id_alias` 로 현재 id 에 잇는다 — 운영자의 판단이
  고아가 되면 같은 글을 두 번 심사한다.
- 위키 `! 위키: name 불일치` 경고는 **통합 오류의 신호**다('페이지 이관' 으로
  읽고 여러 회차 지나쳤다). 답한 경고는 `moved_to`·`excluded` 로 닫는다.

**같은 브랜드 다른 지점** — 시매쓰 7지점은 전부 다른 지점(cmath.co.kr 공식 목록,
`CLAUDE.md` 대조표). 통합 대상이 아니다. 판테라수학은 이름이 달라 별도.

**demo 모드는 통합하지 않는다**(시드 주소가 동 단위라 학군이 한 덩어리).

## 하지 말 것

- 규칙을 넓히기 전에 **묶이면 안 되는 짝**을 먼저 적는다. 정상어학원 ≠ 정상수학학원.
- 신원(id)을 바꾸는 수정은 후기·판정·위키 이관까지 같이 본다. 한 방향 문을 만들지 않는다.
- 공식 지점 목록·전화번호·주소로 교차 확인하기 전에 '같은 학원' 이라 단정하지 않는다.
