`docs/REVIEW_RANKING_AGENTS.md`와 `docs/AGENTS.md`를 읽는다.
`run.py --agents replay`, `run.py --agents status`, 관련 파이프라인 테스트를 확인한다.
실제 수집 시각과 `pending.json`, `last_cycle.json`, 앱 데이터의 생성 시점을 대조한다.

- 실제 기존 게이트를 거쳐 재채점한 결과만 학습에 반영했는가.
- 반복 URL·PC/모바일 변형·다른 지점 재귀속을 신규 성공으로 보상하지 않았는가.
- 작성일 모름을 수집일로 바꾸거나 카페명을 독립 작성자로 세지 않았는가.
- 실패/차단을 후기 0건이라고 기록하지 않았는가.
- 과거 반례와 정상 후기 양쪽을 보존했는가. 회귀 검증 실패 시 이전 정책을 유지했는가.
- 캐시 실행에 새로운 수집 영수증이 없다면 학습 횟수도 그대로인가.

수집 효율은 정확도와 다르다. 사례 기대값·가중치를 테스트 통과를 위해 고치지 않는다.
확인한 결과와 남은 대기를 구분해 보고하고, 배포하지 않았으면 배포 완료라고 적지 않는다.

`docs/PARENT_DECISION_AGENTS.md`의 신규 공식 사실 조사와 기존 후기 학습을
구별한다. 연락처·시간표 공식 페이지가 후기 성공으로 보상되지 않았는지 확인한다.
개인 조건 판정은 `decision-quality-verifier`의 별도 검증이며, 기존 회귀 통과만으로
새 추천 기능의 정확도를 입증했다고 보고하지 않는다.
