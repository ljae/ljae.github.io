# 학부모 의사결정 개선 회차

1. `docs/PARENT_DECISION_DESIGN.md`, `docs/PARENT_DECISION_AGENTS.md`, `docs/PARENT_VOICE_DESIGN.md`, `docs/PARENT_DECISION_SOL_HANDOFF.md`, 현재 git
   상태를 읽는다. 이번 요청이 조사·설계·구현 중 어디까지인지 정하고 기존 코드와
   데이터에서 현재 상태를 확인한다. 이미 받은 권한을 다시 묻지 않는다.
2. 최신 조사나 사용자 과제가 필요하면 `parent-insight-researcher`에 맡긴다.
   독립된 경쟁군 조사만 필요에 따라 병렬화하며, 서로 의존하는 판단은 순서대로 한다.
3. `decision-planner`가 과제 하나, 사실 누락, 변경 파일, 수락 기준·반례·복귀 경로를
   구체화한다. 설계 요청이면 문서·시안·에이전트 지침을 완성한다.
4. 구현 요청이면 누락된 공식 사실은 `decision-evidence-researcher`가 후보로
   조사하고 기존 gate 담당이 범위를 검토한다. 확인되지 않은 필드는 unknown으로
   두고 가능한 비교 기능을 계속 구현한다. 후보를 자동 승인하지 않는다.
5. `decision-engineer`는 비교·연락 adapter·의견 API/권한을, `app-reviewer`는 UI를 담당한다.
   같은 파일을 두 역할이 동시에 고치지 않는다. 산식 변경을 끼워 넣지 않는다.
6. `decision-quality-verifier`가 변경안을 독립 검토한다. 실패는 원 담당에게 돌려
   수정하고 관련 검사만 다시 실행한다. 별도 역할 실행이 불가능하면 자체 점검임을
   명시하고 독립 검증을 했다고 보고하지 않는다.
7. 산출물·검증 결과·미확인·미구현·운영 반영 여부를 구별해 보고한다. 배포가 요청된
   경우 기존 배포 절차와 `/verify-landed`를 따른다. 이 스킬은 외부 메시지 발송이나
   학원 예약을 승인하지 않는다.

V2 DB/API·Flutter 코드는 추가됐다. 현재 운영 적용 상태는 `docs/PARENT_DECISION_IMPLEMENTATION.md`를 읽는다. 이 절차는 프로젝트 역할 호출이며
`run.py --agents`의 후기 조사 명령과 혼동하지 않는다.

V2 정책: 예산 입력·가격 비교·금액 추정은 제외하고 비용은 문의 질문으로만 다룬다.
연락처는 지점·원출처·확인 시점의 실제 근거를 유지한다. 학부모 일반 의견은
비공개로 접수하고 기존 정정/후기 권한을 보존한다. 에이전트는 운영 의견 원문이나
접수 비밀을 Git에 쓰거나 자동 공개·학원 전달하지 않는다. Sol 구현 준비 요청이면
프롬프트·S0~S5·수락 기준까지 완성하고 후속 모델을 지금 실행했다고 주장하지 않는다.
