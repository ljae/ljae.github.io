# 연락처·학부모의 소리를 중심으로 한 V2 리디자인

2026-10-18 · 제품 구현 전. [현재 설계](../PARENT_DECISION_DESIGN.md) · [Sol 인계](../PARENT_DECISION_SOL_HANDOFF.md) · [연락처 실측 원장](parent-contact-baseline-2026-10-18.json)

## 1. 설계가 바뀐 근거

사용자는 예산 정보가 후기에서 확인되지 않고 변동성이 커 정보 신뢰성을 해칠 수 있다고 지적했다. 이에 예산 입력·가격 비교·예산 적합 판정·가격 수집을 신규 기능 범위에서 제외한다. 비용은 직접 문의 질문으로만 다룬다. 이는 모든 학부모가 가격에 무관심하다는 시장 결론이 아니라 **제품이 현재 책임 있게 제공할 정보의 경계**에 대한 결정이다.

[이전 조사](parent-decision-research-2026-10-18.md)의 경쟁 서비스·공식 통계 관찰은 보존한다. V1의 비용 관련 제품 제안과 일정은 V2가 대체한다. 경쟁사 전체가 가격을 잘못 제공한다거나 전화 연결만으로 선택 문제가 해결된다고 주장하지 않는다.

## 2. 현재 코드와 자료에서 확인한 것

| 관측 | 의미와 구현 과제 |
|---|---|
| academies.json 2,868건, tel 비어 있지 않음 2,154건, homepage 1,114건 | 직접 연락 경로를 우선 개선할 기반. 유효성/지점 일치/연결 성공은 별도 확인 필요 |
| registry.json 2,483건에 tel/homepage 없음, RegistryEntry에도 필드 없음 | 등록부 상세는 공백 상태를 지원. 원자료가 확보되기 전 없는 값을 연결하지 않음 |
| 두 자료에 contactSources 필드 없음 | 신규 출처 adapter 설계 필요. 기존 필드에 다른 근거가 있는지 조사하되 확인일을 일괄 생성하지 않음 |
| ContactCard·ConsultChecklist·callAcademy/copyTel/openHomepage 존재 | 이미 있는 흐름을 개선. 새 상담 중개 서비스가 아님 |
| openExternal에는 scheme 검사, openHomepage는 별도 Uri.parse 후 열기 | 외부 URL 검증 정책을 공용화하고 잘못된 URL은 실행/복사 모두 막기 |
| academy_actions SQL 허용 값은 call/reserve/copy_tel/map, 앱은 homepage 기록도 요청 | 선언된 스키마와 앱 불일치. 로그 실패는 삼켜져 UI에서 드러나지 않을 수 있음. 실제 운영 DB 상태는 미조회 |
| corrections는 연락처와 본문 길이 제약, user_reviews는 로그인 경로 | 가벼운 서비스 의견용 신규 비공개 계약 필요. 기존 제약을 임의 완화하지 않음 |
| evidence_reports·claim_disputes·기존 case/gate 운영 존재 | 정보 오류는 담당 경로에 연결. 일반 의견을 검증 사실·평점으로 사용하지 않음 |

필드 유무 측정은 로컬 스냅샷에 대한 것이다. 모든 전화의 통화 가능성이나 홈페이지의 최신 운영 상태를 조사한 수치가 아니다. 원장에 파일 SHA-256과 기준 커밋을 남겼다.

## 3. 최근 디자인 흐름의 적용

Webflow의 2026 전망(2026-01-08)은 고유한 브랜드 표현, 수작업 느낌, 간결한 문구, 요약에서 선택적으로 깊어지는 탐색을 소개한다. 이를 학원실록에는 ‘기록장’과 고민에 반응하는 질문으로 적용한다. 유행을 이유로 강제 스크롤·대형 영상·여러 효과를 추가하지 않는다. 이는 편집자의 전망이며 시장 전체의 채택률이나 성과 실험은 아니다. [공식 원문](https://webflow.com/blog/web-design-trends-2026)

NN/g의 2025 폼 설계 원칙은 질문 구조·요구 사항의 투명성·명확한 표현·도움 제공을 강조한다. 학부모 의견에는 유형 하나와 선택 메모만 먼저 제시하고, 연락처가 필요한 정정 폼으로 전환할 때 차이를 설명한다. 이 자료로 이 제품의 응답률 증가를 수치 예측하지 않는다. [공식 원문](https://www.nngroup.com/articles/4-principles-reduce-cognitive-load/)

선택한 오프닝은 **‘우리 아이의 다음 장’**. 다른 후보인 ‘고민의 지도’는 분류 데이터가 충분할 때, ‘우리 동네 편집실’은 정기 콘텐츠 운영이 가능할 때 검토한다. 시안의 모든 고민 문구·학원·상태는 예시이며 실사용자의 인용이나 실시간 집계가 아니다.

## 4. 학부모 관심사의 수집과 활용

직접 목소리를 들을 경로는 두 겹이다. 상시 서비스 의견은 실제 막힌 지점을 찾고, 별도의 5~8명 과제 관찰은 의견을 내지 않는 사람도 왜 망설이는지 확인한다. 인터뷰 참가자를 모집하거나 외부 연락을 수행하지 않았다.

반복 의견은 같은 문제가 여러 페이지·학년·지역에서 나타나는지 확인한다. 익명 요청 건수를 고유 사람 수로 취급하지 않는다. 심각도·재현성·영향 범위·수정 가능성을 함께 보고 구현 순서를 정한다. 같은 말을 많이 받은 학원이 순위나 홍보 노출을 얻는 구조가 아니다.

기능 가설과 반증:

| 가설 | 반증 신호 | 다음 조치 |
|---|---|---|
| 고민 선택이 문의 질문 준비를 돕는다 | 칩을 추천 정확도 인증으로 오해, 탐색 시간 증가 | 질문용임을 명확히 하거나 선택 단계를 줄임 |
| 연락처와 질문을 붙이면 문의 준비가 쉬워진다 | 출처를 못 찾거나 다른 지점으로 전화 | 지점 표시·출처를 먼저 수정, 해당 연락 행동 보류 |
| 짧은 비공개 의견이면 문제를 더 쉽게 남긴다 | 메모 부담·접수 여부 혼란·반복 실패 | 필드/상태/재시도 개선, 백엔드 없는 제출 비활성 |
| 개선 기록이 의견의 가치를 보여준다 | 접수와 반영을 혼동, 기록이 실제 배포와 다름 | 상태 용어 수정, 배포 검증 연결을 출시 조건으로 강화 |

## 6. 시안 자체 검증 기록

2026-10-18, 로컬 HTTP 서버·Playwright·설치된 Chrome으로 실행했다. [결과 JSON](parent-v2-prototype-check-2026-10-18.json)에 최종 HTML 해시를 남겼다.
