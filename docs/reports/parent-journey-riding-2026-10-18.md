# 고민 연결과 라이딩 비교 개선

2026-10-18. **운영 배포·실제 사이트 검증 완료**. 자체 구현·검증 기록이며 독립 에이전트 검증은 아니다. 운영 배포 증거는 아래에 별도로 기록한다.

## 문제와 변경

첫 화면의 고민 선택이 이후 경험에서 잘 드러나지 않았다. 기존에는 오프닝 질문과 비교 순서에 주로 반영되었다. 이제 선택한 고민을 탐색·목록·상세에서 확인/변경하고, 해당 과목·학년의 실제 원문 발췌 또는 지점 공식 안내를 먼저 읽는다. 자료가 없으면 공백과 관련 질문을 제공한다. 같은 상태가 비교 우선 항목과 문의까지 이어진다.

`라이딩과 하원 시간이 걱정돼요`를 네 번째 고민으로 추가했다. 라이딩은 시간표/보강과 분리된 비교 항목이며, 등록부 전용 학원도 상세와 비교에서 주소·지도·셔틀 정류장/요일·하원·픽업 질문을 확인할 수 있다.

가정마다 다른 이동 부담은 직접 적은 메모로 비교한다. 이동 방법, 확인한 편도 시간, 주간 횟수, 하루 보호자 이동/대기 합계, 검토 중인 하원 시각, 개인적인 동선 판단을 학원/과목/학년별로 보관한다. 하루 보호자 시간×주간 횟수가 모두 있을 때만 주간 부담을 계산한다. 입력값과 입력일을 표시하며 학원의 확인된 운영 정보로 표시하지 않는다.

메모는 해당 브라우저에만 남는다. 집/학교 주소·아이 이름을 받지 않으며 서버·분석 이벤트·공유 링크로 보내지 않는다. 각 반의 메모만 삭제할 수 있고 새로고침 후 복원된다. 문의 복사 시 개인 하원 시각·주간 횟수가 포함됨을 알린다. 예산·가격 추정, 점수·순위 변경은 없다.

## 운영·설계 경계

1차 운영 검사에서 자료 로딩 중 탐색 버튼이 이름 검색창을 열던 기존 분기 오류를 발견했다. 로컬의 빠른 응답에서는 드러나지 않았다. 탐색 요청을 보관하고 자료가 준비된 다음 같은 고민으로 탐색 영역에 이동하도록 수정했다. 로딩 실패 때도 선택을 유지하며 재시도할 수 있다. 새 위젯 반례는 지연→오류→재시도→탐색 위치를 확인한다. 실제 웹 검사도 첫 학원 데이터 응답을 탐색 클릭 뒤까지 보류해 같은 조건을 강제로 재현한다. 검색창을 원하는 사용자는 별도의 이름 검색 행동을 계속 사용할 수 있다.

지도 목적지 연결 검사는 실제 통학 경로·시간 검증이 아니다. 셔틀 운행 여부·정류장·수업 종료 시각은 현재 반에 직접 확인해야 한다. 비교 글은 기존 검토 목록을 유지하며 새 라이딩 정보를 자동 부여하지 않았다. 실제 학부모 이동 자료를 수집하거나 서버에 전송하지 않았다. 백엔드와 가격/점수 산식은 수정하지 않았다.

에이전트 계약과 구현/검증 프롬프트에도 고민 동선, 개인 메모와 공개 사실의 분리, 저장 범위, 주간 계산, 공유 제외 반례를 반영했다. [구현 계약](../PARENT_DECISION_IMPLEMENTATION.md), [에이전트 계약](../PARENT_DECISION_AGENTS.md), [반례 명세](../evals/parent-decision-cases.yaml)를 따른다.
