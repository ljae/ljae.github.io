# 학부모 V2 배포 검증 — 2026-10-18

사용자의 전체 검증·웹 배포 요청에 따른 릴리스다. 이 기록의 최종 배포 결과는 실제 GitHub Actions와 운영 화면 확인 후 갱신한다. 로컬 코드 완성이나 서버 구성만을 웹 배포 완료로 간주하지 않는다.

## 릴리스 범위

- 고민을 고르는 오프닝, 최대 3곳의 과목·학년·관심사별 비교, 항목의 선택 의미와 원문·시점·범위 표시.
- 2~3곳을 함께 다루는 본문 검토 글 4편. 전체/일부 비교와 지점·브랜드 연결 수준을 표시하고 원문으로 연결한다. 모든 학원 조합에 글이 있는 것은 아니다.
- 가격 추정·예산 점수 없이 학원별 연락처와 질문 복사 제공.
- 비공개 학부모 의견의 접수·확인 코드 조회·삭제, 관리자 검토와 별도 공개 개선 기록.
- 운영 배포 워크플로에서 세 기능 플래그 활성화. 의견 DB·HTTP 회귀 검사를 배포 필수 단계로 추가.

## 검증 중 발견해 수정한 문제

1. **기존 배포의 URL 제거 차단:** 최근 야간 데이터 `f37850766f86156b59585c59a63af5019632ddc6`의 배포는 `UNEXPECTED_URL_REMOVAL:30`으로 실패했다. 직전 성공 배포 `241e5bb5df13023d02b74428c30eed9e5ae6f884`의 원장과 현재 공개 자료를 대조했다. 이전 ID `14206`은 현재 학원 `1000031310`의 명시된 등록 구성원이라 검증된 별칭으로 연결했다. 주소가 달라 동일 주소라고 주장하지 않는다. 나머지 29개는 폐원·이전으로 단정하지 않고 ‘최신 자료에서 확인하지 못했습니다’라는 noindex 안내 페이지를 유지한다. 삭제 방지 검증은 유지하며 안내 페이지가 다음 배포에서 사라져도 실패한다.
2. **의견 삭제의 SDK 응답:** Supabase SDK는 본문 없는 HTTP 204를 빈 문자열로 반환했다. 이를 JSON map으로 캐스팅하던 앱을 수정하고 실제 SDK를 통한 회귀 테스트를 추가했다.
3. **요청 제한의 IP 출처:** 실제 게이트웨이에서 X-Forwarded-For는 다중 체인이며 클라이언트가 바꿀 수 있었다. 단일 `cf-connecting-ip`를 사용하고 위조 입력에 대한 게이트웨이 403을 확인했다. 원시 IP는 저장하지 않으며 전용 비밀로 HMAC 처리한 제한 키만 저장한다.

IP 헤더의 의미는 [Cloudflare 공식 문서](https://developers.cloudflare.com/fundamentals/reference/http-headers/), 함수 배포는 [Supabase 공식 문서](https://supabase.com/docs/guides/functions/deploy)를 참고했다. 이 배포의 신뢰 헤더 선택은 문서와 실제 게이트웨이 검사에 근거한 판단이며, 호스팅 변경 시 다시 검증해야 한다.

- 의견 내용·맥락 90일, 접수 기록 180일 안내를 앱에 표시했다. `parent-voice-maintenance.yml`은 매일 10:10 KST 보관 기한 정리를 실행한다.

## 배포와 브라우저 확인

- 공개 Supabase 설정을 넣은 release 빌드 통과. 앱 번들·커밋 대상에 환경 파일의 서버 비밀이 포함되지 않았음을 검사했다. JavaScript 배포에서 사용하지 않는 wasm 시험 컴파일은 생략한다.
- 브라우저 미리보기: 운영 origin에서 로컬 release 파일을 제공하고 실제 운영 API로 의견 1건을 접수 201 → 조회 200 → 삭제 204로 확인했다. 삭제 뒤 sessionStorage 접수증도 제거됐고 브라우저 오류 0이다.

## 검증 범위의 한계

관리자 인증 후 전체 큐 조작은 운영 브라우저에서 수행하지 않는다. DB 권한과 관리자 상태 전이는 실제 SQL을 이용한 로컬 PostgreSQL 검사로 확인하고 운영에서는 익명 접근 차단을 확인한다. 비교 글의 모든 외부 사이트를 지속 감시하는 기능은 없으며 자료 검토 시점·미확인 범위를 표시한다. 에이전트 역할 명세는 추가됐지만 상시 다중 에이전트 서버나 독립 에이전트 검증을 실행한 것은 아니다.
