# 학원 소개 출처의 직접 갱신

2026-09-19 확인: 강남엄마의 robots.txt는 공개 소개 경로를 허용하지만, 소개 페이지에 수집기 User-Agent로 요청하면 HTTP 403을 반환한다. Aside에서 일반 페이지는 열리는 것을 확인했다. GitHub 운영 수집에서도 소개 40곳의 직접 요청이 모두 실패했다. robots 허용은 HTTP 접근 허용과 별개다. 사용자는 현재 제휴 API나 자동 수집 허가를 보유하지 않았다고 확인했다.

직접 갱신은 아직 복구되지 않았다. 인증된 제휴 API 또는 출처 운영자가 허용하는 수집 방식이 필요하다. 브라우저 위장, 프록시, 다른 네트워크로 접근 제한을 우회하지 않는다. 네이버 검색 API는 별도로 정상 동작하지만 검색 결과 확인일을 소개 원문의 재확인일로 사용하지 않는다.

## 적용한 실패 처리

- 수집기를 `openedu-bot`으로 식별한다. 401/403/429 응답 이후 동일 호스트 요청을 중단하며, 실행 간에도 상태를 캐시에 보존한다. 다음 날 한 번 재확인한다.
- 정상 자료의 `fetched_at`은 성공 확인일이다. 통신·접근 실패는 `last_attempt_at`과 `last_error`에 기록하며 기존 성공 자료를 덮어쓰지 않는다.
- 일부 학원만 갱신돼도 다른 학원의 마지막 검증 자료는 유지한다. 404/410 또는 등록부 불일치가 확인된 자료는 제거한다. 전체 제거 결과를 빈 파일 보호 규칙으로 되살리지 않는다.
- 공개 출처 카드에 자동 재확인 실패와 이전 확인일 유지 사실을 표시한다. Actions 요약에도 직접 갱신 HTTP 상태와 시도일을 별도로 기록한다.
- `셔틀 정보 없음`은 제공 여부 미상으로 처리한다. 구 파서의 셔틀 주장은 원문 재확인 전 보류한다. 대상 학년·과목 등 다른 검증 정보는 유지한다.

## 허용 후 확인 절차

제공받은 연동 방식·호출 한도에 맞춰 수집기를 설정한다. 자동 수집이 허용된 상태에서 소개 전용 `collect.yml` 실행(`directory_only=true`)으로 실제 원문 또는 제공 API의 응답을 확인한다. 이름·주소 불일치는 보류하고 성공한 자료만 확인일을 갱신한다. 공개 결과와 운영 로그를 대조한 뒤 자동 배포를 확인한다.
