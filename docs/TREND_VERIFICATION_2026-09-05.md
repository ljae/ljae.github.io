# 검색어 트렌드를 화제성에 쓸 수 있는가 — 검증 (2026-09-05)

네이버 **지역검색**과 **검색어 트렌드(데이터랩)** 를 새로 붙였다는 말을 받고,
트렌드를 랭킹의 화제성에 넣을 수 있는지 확인했다.

## 결론 먼저

| | |
|---|---|
| **점수(화제성)에 넣는다** | **안 된다.** 아래 ①②③ 중 어느 하나도 우회할 방법이 없다 |
| **수집 우선순위에 쓴다** | **된다.** `demand.py`·`actions.py` 와 같은 층. 권한다 |
| **브랜드 화면에 따로 보여준다** | 된다. 단 '이 브랜드' 라고 적어야 한다 |

셋을 다 통과해 점수에 쓸 수 있는 학원은 **956곳 중 63곳(7%)** 이고,
그 63곳은 대체로 이미 표본이 두꺼워 화제성을 잘 재고 있는 곳이다.
**얻는 것이 가장 적은 자리에만 쓸 수 있다.**

## 지금 상태

엔드포인트는 찾았다. 검색과 도메인이 다르다.

    검색      https://naverapihub.apigw.ntruss.com/search/v1/...     200 정상
    지역검색   https://naverapihub.apigw.ntruss.com/search/v1/local   200 정상 ✓ 새로 켜짐
    데이터랩   https://naveropenapi.apigw.ntruss.com/datalab/v1/search  401

```
{"errorCode":"210","message":"Permission Denied","details":"A subscription to the API is required."}
```

같은 키로 지역검색은 200, 데이터랩은 401 이다. **구독이 이 키에 아직 안
걸려 있다.** 다른 애플리케이션에 붙었거나 developers.naver.com 쪽에
만드셨다면 그쪽 Client ID/Secret 이 따로 필요하다.

클라이언트와 점검 명령은 넣어 두었다 — 구독이 붙는 즉시 확인할 수 있다.

```bash
.venv/bin/python pipeline/run.py --trend
```

## ① 값이 절대량이 아니다 — 요청이 다르면 비교할 수 없다

데이터랩은 **한 요청 안에서 최댓값을 100 으로 놓은 상대비**를 준다.
한 요청에 키워드 그룹 5개까지다. 956곳을 줄 세우려면 최소 192번 요청해야
하고, 각 요청의 100 은 서로 다른 100 이다.

우회법은 있다 — 모든 요청에 같은 **기준 낱말**을 넣고 그 값으로 나눈다.
그런데 기준을 크게 잡으면(예: '대치동 학원') 작은 학원이 전부 0 으로
반올림되고, 작게 잡으면 큰 학원이 기준을 눌러 서로 구별되지 않는다.
**우리 랭킹은 코호트 z 점수를 쓰므로 분포의 모양이 곧 등수인데, 그 모양이
기준 낱말 선택에 좌우된다.** 그건 측정이 아니라 우리 선택의 그림자다
(CLAUDE.md: '연출·보정 값을 넣을 때 물을 것 — 그 값의 x축을 누가 만드는가').

## ② 검색어는 브랜드 단위인데 우리 랭킹은 지점 단위다 — 이것이 결정적이다

'시매쓰' 를 검색한 사람이 도곡점을 찾는지 반포점을 찾는지 알 수 없다.
**그리고 규모가 클수록 지점이 여럿이다.**

| 표본 | 학원 | 형제 지점 있음 | 비율 |
|---|---|---|---|
| 100건+ | 54 | 29 | **54%** |
| 30~99 | 65 | 15 | 23% |
| 10~29 | 70 | 11 | 16% |
| 1~9 | 213 | 22 | 10% |

검색량이 잡힐 만한 곳(표본 100+)의 **절반 이상이 지점이 여럿**이다 —
시매쓰·청담어학원·폴리·정상·에이프릴·한우리·깊은생각·개념폴리아·트윈클…
전부 여기 해당한다.

**우리는 바로 이 문제를 방금 없앤 참이다.** 2026-09-05 결정 D3 으로
'지점 불명 글은 근거로 쓰지 않는다' 를 적용했다(1,335건 제외). 시매쓰 네
지점이 같은 근거로 2·3·4위에 나란히 서던 것을 고친 것이다.
검색량은 **본질적으로 지점 불명**이라, 점수에 넣으면 그 결정을 정면으로
되돌리게 된다.

## ③ 이름이 검색어가 못 되는 곳이 있고, 여기서는 걸러낼 방법이 없다

    검색어로 쓸 만한 이름(알맹이 3자 이상 · 일상어 아님)   735곳 (77%)
    못 쓰는 곳                                        221곳 (23%)
      와이키즈대치개포학원 · 강남미술교습소 · 원리과학교습소 · 나사과학교습소 …

이건 우리가 이미 아는 문제다 — '새로운학원'·'최상위수학'·'대치학원'.
**차이는 여기서는 고칠 수가 없다는 것이다.** 후기에는 본문이 있어서
게이트를 걸 수 있었다(이름 자리·학원 표지·남의 학원 이름·타지역 동).
검색량에는 **글이 없다.** '최상위수학' 검색량이 문제집을 찾는 사람인지
그 교습소를 찾는 사람인지 물어볼 데가 없다.

우리 게이트 구조 전체(`name_spans`·`is_generic_academy`·`RivalIndex`·
`foreign_dong`)가 텍스트에 걸려 있고, 트렌드에는 적용할 수 없다.

## 셋을 다 통과하는 곳

    지점 단일  ∩  이름 쓸 만함  ∩  표본 30건 이상   =   63곳 / 956  (7%)

    대치이지영어학원 · 부엉이학원 · 강남하이퍼학원 · 에디센어학원 ·
    그로튼아카데미학원 · 렉스김어학원 · 그로튼에밀튼어학원 · 프라우드세븐학원 …

이 63곳은 **이미 표본이 30건 이상이라 화제성을 잘 재고 있는 곳**이다.
트렌드가 보태 줄 것이 가장 적은 자리다. 반대로 정말 도움이 될 곳
(표본이 얇아 화제성을 못 재는 곳)은 검색량도 0 으로 온다.

## 그러면 어디에 쓰나 — 수집 우선순위

**이 저장소에는 이미 그 자리가 있다.** `demand.py`(모은 글에 이름이 몇 번
나오는가)와 `actions.py`(학부모가 전화·복사를 눌렀는가)가 같은 층이다.
둘 다 **점수에는 안 쓰고 다음 회차에 무엇을 볼지에만** 쓴다.

    학부모가 많이 찾는 학원은 근거를 더 찾아야 할 학원이지
    점수가 높은 학원이 아니다.  (actions.py 주석)

검색어 트렌드는 이 문장에 정확히 들어맞는다. 브랜드 단위여도 되고,
상대비여도 되고, 이름이 헐거워도 된다 — **순서를 정하는 데는 대략이면
충분하고, 틀려도 화면에 실명으로 남지 않는다.**

### 제안하는 사용법

1. **브랜드 단위로 묶어 질의한다.** 지점이 아니라 브랜드가 검색 단위다.
   `dedupe.brand_token` 으로 묶어 한 요청에 5개씩.
2. **기준 낱말을 하나 고정해 모든 요청에 넣는다.** 회차마다 같은 것을 써야
   추세가 우리 요청 구성이 아니라 실제를 가리킨다.
3. **결과는 `demand` 와 같은 형식으로 `.cache` 에 쌓고 선정 가산점으로만
   쓴다.** 점수·화면에는 넣지 않는다.
4. 이름이 검색어로 못 쓸 곳(221곳)은 **아예 질의하지 않는다.** 값이 와도
   그 학원 것이 아니다.

이렇게 하면 형제 신호(B3)·수요 신호와 함께 '아직 안 본 곳' 을 고르는 근거가
하나 더 는다. 지금 채점 대상 956곳 중 **554곳이 표본 0** 이라, 무엇을 먼저
볼지가 실제로 가장 아쉬운 자리다.

## 나중에 다시 볼 것

- **추세(방향)만 쓰는 길은 남아 있다.** 절대 비교는 못 해도 한 학원의
  6개월 상승·하락은 그 학원 안에서 일관된다. 지금 화제성의 추세 항목은
  '작성일을 아는 글이 9%뿐' 이라 대부분 '보합' 이다. 지점이 하나뿐이고
  이름이 또렷한 63곳에 한해 **추세 보조 지표**로 쓰는 것은 검토할 만하다.
  단 그때도 화면에 '검색 추세' 라고 따로 적어야 한다 — 후기에서 온 값과
  섞으면 그 숫자가 무엇인지 설명할 수 없다.
- 구독이 붙으면 `--trend` 로 **실제 값의 모양**을 먼저 본다. 위 판단은
  API 의 문서화된 성질과 우리 데이터 구조로 한 것이고, 소규모 교습소가
  실제로 0 으로 오는지는 값을 받아 봐야 확정된다.
