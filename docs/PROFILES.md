# 학원 프로필 — 후기 N건을 한 장의 카드로 (2026-09-17)

한 학부모가 AI 로 오픈채팅·검색 결과를 긁어 정리한 블로그
(blog.naver.com/greenyulma/224374345103, '대치 영어학원 정보 요약')가
**실제 체감과 가깝다**는 평가를 받았다. 그 글의 형식이 답이었다 — 학원마다
네 칸: **선호·레테 / 커리큘럼·숙제 / 잘 맞는 아이·주의 / 위치·운영.**
점수 한 줄로는 안 읽히던 것이 이 네 칸으로 읽힌다.

우리는 같은 카드를 **우리 근거로** 만든다. 그 블로그와 다른 점 둘.
1. 모든 문장이 **원문 인용**을 갖는다. 인용이 원문에 글자 그대로 없으면
   그 문장은 버린다(`claim_llm.verify` 와 같은 규칙). 지어낼 자리가 없다.
2. **점수에 쓰지 않는다.** 산식은 결정적으로 남는다(요약·사실 추출과 같은 층).

랭킹 화면의 '맞춤' 필터는 없앴다. 관점 감성(±45자 낱말)으로 '선생님 평
좋은' 을 거르는 것은 근거가 얇고, 학부모가 실제로 묻는 것('우리 애한테
맞나')에 답하지 못했다. 그 자리를 이 카드가 맡는다.

## 화면 계약 — `academies.json` 의 `profile`

```jsonc
"profile": {
  "version": 1,
  "generatedAt": "2026-09-17",
  "model": "gemini-3.7-flash",          // 어느 모델이 썼는지 밝힌다
  "sample": 42,                          // 모델이 읽은 발췌 수
  "sources": 42,                         // 그중 서로 다른 글 수
  "levelTest": {                         // null 이면 근거 부족
    "band": "S",                         // S+ · S · A+ · A · B+ · B · C
    "hard": "컷·라이팅",                  // 무엇이 어려운가 (≤12자). 문제 자체 vs 컷·인터뷰
    "note": "문제보다 합격·라이팅 컷이 어렵다는 평",
    "quotes": [Q, Q]
  },
  "homework": { "load": "중상", "note": "…", "quotes": [Q, Q] },   // 상·중상·중·중하·하
  "curriculum": { "note": "…", "quotes": [Q, Q] },
  "fit": { "goodFor": ["말하고 참여하며 책을 좋아하는 아이"],
           "caution": ["반·교사차 확인"], "quotes": [Q, Q] },
  "ops": { "note": "셔틀 없음 · 주차 협소", "shuttle": false, "quotes": [Q] },
  "oneLiner": "레테 S · 숙제 중상 · 노블 정독"   // 카드 한 줄. 파이프라인이 결정적으로 짓는다
}
Q = { "quote": "원문 글자 그대로 ≤120자", "url": "…", "urlHash": "…",
      "postedAt": "2026-03-01" | null,
      "kind": "parent" | "self" }        // self = 학원이 스스로 밝힌 것(디렉터리·홈페이지)
```

규칙(파이프라인이 강제한다 — 화면은 믿고 그린다):
- 절(section)마다 **서로 다른 글 2건 이상**의 검증된 인용이 있어야 절이
  나간다(`ops` 만 1건). 모자라면 `null`. 화면은 null 절을 '아직 근거 부족'
  으로 적는다 — 빈칸으로 두지 않는다.
- 인용은 ≤120자, 원문 글자 그대로(띄어쓰기만 무시). 사람 이름·아이 점수는
  모델에게 빼라고 하고, 검증 뒤에도 `01[016-9]-` 전화·이메일 꼴은 버린다.
- `band`·`load` 는 위 어휘 밖이면 절 전체를 버린다.
- `kind: self` 인용만으로는 `levelTest`·`homework`·`fit` 을 만들지 않는다 —
  학원이 스스로 '숙제 적당' 이라 말한 것은 학부모 후기가 아니다.
- `oneLiner` 는 파이프라인이 `band`·`load`·`curriculum.note` 앞 12자로
  짓는다. 모델 문장을 그대로 카드에 올리지 않는다.

## 파이프라인

`pipeline/edutree/profiles.py` — 흐름:

    build.run  →  게이트·주장 뒤, export 앞
      1. 학원별로 근거(is_excluded 아님) 를 신뢰도순 40건까지 고른다
         (표본 15건 미만은 만들지 않는다 — OPENEDU_PROFILE_MIN_SAMPLE)
      2. 각 글에서 evidence.excerpt 로 **이름 곁 300자**를 뽑아 번호를 매긴다
         [1]…[40] + (있으면) [S1] 학원 자기 서술(directory.py)
      3. LLM 에 JSON 만 요구한다. 인용마다 `ref` 번호를 함께.
      4. verify: quote 가 excerpt[ref] 에 글자 그대로 있는가. 아니면 그 인용을
         버린다. 절의 검증 인용이 문턱 미만이면 절을 null.
      5. 캐시 `.cache/profiles.json`: {id: {fingerprint, result}}.
         fingerprint = sha1(정렬된 url_hash 목록 + PROMPT_VERSION).
         근거 목록이 20% 넘게 바뀌었거나 30일 지났을 때만 다시 만든다.
      6. 한 실행 상한 OPENEDU_PROFILE_PER_RUN(기본 40). 제공자·모델·치명
         오류 처리는 summarize.py 의 것을 그대로 쓴다.

`--from-cache` 는 캐시만 읽는다(요약·사실 추출과 같다).
`OPENEDU_PROFILE_PER_RUN=0` 이면 LLM 을 부르지 않는다.

## 소스를 넓히는 것

블로그 글이 오픈채팅·검색을 긁었듯, 우리도 카페·블로그 API 밖을 본다.
단 **robots.txt 를 먼저 보고, 막으면 안 읽는다.** 도구를 바꿔 우회하지 않는다.

| 출처 | 무엇을 주나 | 방법 | 상태 |
|---|---|---|---|
| 네이버 지식iN (`kin`) | '어디가 좋나요' 문답 | 검색 API | 콘솔 미활성 |
| 네이버 웹문서 (`webkr`) | 티스토리·강남엄마·디스쿨 등 카페 밖 글 | 검색 API | 콘솔 미활성 |
| 네이버 뉴스 (`news`) | 학원 관련 보도(홍보 기사 포함 — 신뢰도 낮게) | 검색 API | 콘솔 미활성 |
| 강남엄마 학원 소개 (`gangmom.kr/institute/*`) | 학원 **자기 서술**(대상·셔틀·설명회) | robots 허용 · `/review/` 는 거부 | `directory.py` |
| 오늘학교 아카데미 (`academy.prompie.com`) | 학부모 후기·별점 | `Content-Signal: ai-train=no` → 우리 규칙상 안 읽는다 | 보류 |

세 API 는 NCP 콘솔에서 '검색 > 지식iN·웹문서·뉴스' 를 켜면 다음 수집부터
붙는다(코드는 이미 그 소스를 안다). 웹문서가 켜지면 강남엄마·디스쿨 페이지
링크가 언급으로 들어오고, `directory.py` 가 그중 허용된 디렉터리 페이지를
읽어 학원 자기 서술을 `kind: self` 근거로 보탠다.

## 하지 않는 것

- 프로필 문장을 점수·순위·정렬에 쓰지 않는다.
- 인용 없는 문장을 내보내지 않는다. '잘 맞는 아이' 도 인용이 받쳐야 한다.
- 다른 사람의 AI 요약 글(블로그 보고서)을 근거로 옮겨 적지 않는다 — 그 글의
  오류(스와튼GLP·GLP프랩 혼동)까지 우리 것이 된다. 원문 후기만 읽는다.
