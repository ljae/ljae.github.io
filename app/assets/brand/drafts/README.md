# 로고 시안 — A안 「판면 + 경로」 (2026-08-29)

실록 판면의 세로 괘선(계선) 다섯 줄 중 하나가 계단처럼 올라간다.
**기록(계선)과 테크트리(경로)를 한 그림**으로 둔 것이 이 안의 전부다.
주묵은 도착점 하나에만 찍는다 — 도장을 브랜딩에 쓰지 않기 위해서다
(`theme.dart`: "도장은 단정할 수 있는 것에만 찍는다").

생성: Gemini 3 Pro Image (nano-banana-pro).
**시안까지다.** 최종은 SVG 로 다시 그린다 — 획 두께가 `AppRule` 토큰
(0.7/1.0/2.0/3.0)인 디자인에서 래스터는 규칙을 지킬 수 없다.

## 1회차 (`*.png`)

| 파일 | 구성 | 판정 |
|---|---|---|
| `a1-canon.png` | 계선 5 + 3단 계단 + 주묵 사각 | 후보. 주묵이 획 끝에 붙은 유일한 것 |
| `a2-dense.png` | 계선 9 + 상승 끝단이 주묵 | **탈락 — 모서리가 둥글다**(알약 금지) |
| `a3-frame.png` | 사주단변 프레임 + 판면 | 프레임이 내용을 이겼다 |
| `a4-minimal.png` | 계선 2 + 2단 계단 | 작은 판 후보 |

`_check-16px.png`: **hairline 계선은 16px 에서 전부 증발한다.** 굵은 계단만
남아 '상승 화살표'로 읽히고 판면이라는 절반이 사라진다. → 큰 판·작은 판을
두 벌로 나눠야 한다. `AppRule.hair = 0.7` 을 로고에 그대로 못 가져온다.

## 2회차 (`r2/`) — 1회차의 셋을 못 박고 다시

각진 캡·미터 코너 / 주묵을 획 끝에 접함 / 계단을 괘선 블록 안에 가둠.

| 파일 | 판정 |
|---|---|
| `r2/b1-page.png` | **큰 판 채택.** 판면이 온전히 읽히는 유일한 것 |
| `r2/b2-page-heavy.png` | **탈락 — 막대그래프가 됐다** |
| `r2/b3-compact.png` | 프레임이 생겨 '격자'로 읽힌다 |
| `r2/b4-minimal.png` | **작은 판 채택.** 16px 에서 형태가 온전한 유일한 것 |

**여기서 배운 것: 계선을 굵히면 판면이 차트로 뒤집힌다.** b2 가 그 증거다 —
계선 사이 흰 칸이 막대로 읽혀, 네거티브에 넣어 둔 `chart bars` 가 그대로
나왔다. "작은 판은 굵히면 된다"는 1회차 결론은 절반만 맞았다. 굵히되
**계선 수를 함께 줄여야** 한다(b4 의 방향).

## 최종 (`final/`, 4K, 편집 모드로 형태 보존)

- `logo-large.png` ← b1. 주묵이 획 폭과 일치하고, 상단 획이 계선을 가로지른다.
  **계단이 3단 → 2단으로 줄었다**(요청하지 않은 변화).
- `logo-small.png` ← b4. `_check-16-32px.png` 에서 16·32px 모두 또렷하다.

### 이때의 결함 — 두 벌이 한 가족으로 안 보였다 (3회차에서 해결)

`logo-small` 은 계선 위의 경로가 아니라 **책 표지**로 읽히고, 주묵도 획보다
넓어 `logo-large` 의 규칙과 어긋난다. 로고 시스템에서 작은 판은 큰 판의
**축약**이어야 하는데 지금은 별개 도안이다.

→ 다음 회차: `logo-large` 의 계단을 그대로 두고 계선만 5 → 2 줄로 줄여
  작은 판을 다시 만든다. 주묵 폭은 두 벌 모두 획 폭과 같게 못 박는다.

## 3회차 (`r3/`) — 작은 판을 큰 판의 축약으로 다시

새로 그리지 않고 `final/logo-large.png` 를 1K 로 줄여(`r3/_src-large-1k.png`)
**입력 이미지로 넣고 계선만 깎았다.** 계단과 주묵은 손대지 말라고 못 박았다 —
축약은 새 도안이 아니다.

| 파일 | 판정 |
|---|---|
| `r3/c1-two-rules.png` | 축약으로 읽히나 계선이 여전히 가늘다 |
| `r3/c2-three-rules.png` | **탈락.** 3줄로 줄이랬는데 4줄이 나왔고 16px 에서 뭉갠다 |
| `r3/c3-two-tight.png` | **채택.** 계선 2줄이 굵고 16px 에서 셋 중 가장 또렷하다 |

`final/logo-small.png` 를 c3 기반으로 교체했다(이전 판은 `r2/b4-minimal.png`
에 남아 있다). `final/_family-check.png` 에서 두 벌이 **같은 계단·같은 주묵**을
공유하는 것을 확인했다.

**축약에서 마감 획(계선 끝의 짧은 가로획)은 뗐다.** 큰 판에는 있고 작은 판에는
없다 — 작아질 때 없앨 것은 기능이 아니라 장식이다(헤더 필터를 접을 때와 같은
판단).

### 아직 남은 것

16px 에서는 '두 줄 사이의 계단' 까지만 읽히고 세부가 사라진다. 이건 래스터를
줄여서 재는 한계이기도 하다 — 실제 파비콘은 벡터를 픽셀 그리드에 맞춰 그리므로
이보다 낫다. **SVG 재작도 때 16px 그리드에 스냅시켜 다시 잴 것.**

## 4회차 (`svg/`) — 래스터를 버리고 좌표로 다시 그렸다

`svg/build_marks.py` 가 좌표에서 SVG 와 검증용 PNG 를 **함께** 낸다. 시안을
눈으로 베끼지 않았다 — 획 두께가 토큰인 디자인에서는 좌표를 손으로 정해야
규칙을 지킬 수 있고, 16px 에서 뭉개지는지도 좌표로만 증명된다.

    logo-mark.svg          큰 판 (계선 5, 획 4:1)
    logo-mark-compact.svg  작은 판 (계선 2, 획 6:3)
    logo-icon.svg          작은 판 + 한지 바탕 — 파비콘·앱아이콘용
    preview/               같은 좌표표로 그린 16·32·64·256px

**격자는 48 단위다.** 48 = 16 × 3 이라 좌표가 3의 배수면 16px 에서 모든
모서리가 정수 픽셀에 떨어진다. 3회차에서 남겨 둔 '16px 에서 세부가 사라진다'
는 이것으로 해결됐다 — **16px 렌더가 256px 과 같은 그림이다.**

**두 벌은 중심선을 공유하고 두께만 다르다.** 계단을 사각형 목록이 아니라
중심선(`STAIR_PATH`)으로 적고 두께를 인자로 받는다. 작은 판이 축약이라는
사실이 파일이 아니라 코드에서 보장된다.

### 여기서 세 번 틀렸다

1. **두 벌을 같은 두께(6)로 뒀더니 큰 판의 가운데가 검은 덩어리가 됐다.**
   굵은 획과 이웃 계선 사이 흰 자리가 3단위밖에 안 남아 글자처럼 읽혔다.
   → 큰 판 4, 작은 판 6. 두께를 달리하는 것은 광학이지 변덕이 아니다.
2. **주묵이 이음매까지 덮어 트레드를 먹었다**(4단위 길어졌다). 중심선을
   살찌울 때 이음매를 늘리는 것이 기본인데, 주묵 구간만은 반대로 물러서야
   한다. 주묵은 트레드 **윗변에 접하는** 것이지 트레드의 일부가 아니다.
3. **XML 주석에 `-`두 개를 넣어 비표준 XML 이 됐다.** CSS 변수 이름을 주석에
   그대로 적은 탓이다. 브라우저는 넘어가지만 엄격한 파서는 거부한다.
   → 파싱 검증을 붙였고 그것이 잡았다.

### 확인 방법

    uv run --with pillow --no-project python app/assets/brand/drafts/svg/build_marks.py

Pillow 로 그린 PNG 와 **크롬이 SVG 를 렌더한 결과가 일치**하는 것까지 봤다.
Pillow 쪽은 재구현이라 그것만으로는 SVG 가 맞다는 증거가 안 된다.

### 아직 안 한 것

**실제 파비콘·앱아이콘을 갈아 끼우지 않았다.** `app/web/icons/*`, `favicon.ico`,
`app/assets/brand/mark.png` 는 옛 남색 로고 그대로다. 로고 교체는 서비스의
얼굴을 바꾸는 일이라 별도 결정이다. 갈아 끼울 때는 서비스워커 캐시 때문에
"그대로다" 라는 피드백이 오기 쉬우니 CLAUDE.md 의 해당 항목을 볼 것.
