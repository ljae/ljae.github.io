# 로고 — 판면 위로 계단이 오른다

계선(界線) 둘 사이로 굵은 획이 계단처럼 올라가고, 그 끝에 주묵이 찍힌다.
**기록**(계선)과 **테크트리**(경로)를 한 그림에 둔 것이고, 이 서비스가 하는
일 그대로다. 주묵은 도착점 하나에만 쓴다 — 로고 전체를 도장으로 만들면
'검증'에만 쓰기로 한 신호를 브랜딩에 써 버린다(`theme.dart` 참고).

    logo-mark.svg          큰 판. 계선 5, 획 4:1 — 소개·인쇄·큰 화면
    logo-mark-compact.svg  작은 판. 계선 2, 획 6:3 — 헤더·아이콘
    logo-icon.svg          작은 판 + 한지 바탕 — 파비콘·앱아이콘
    preview/               검증용 렌더 (16·32·64·256·512px)

## 고칠 때

```bash
uv run --with pillow --no-project python brand/build_marks.py   # SVG + preview
uv run --with pillow --no-project python brand/build_icons.py   # 파비콘·앱아이콘 전부
```

`build_marks.py` 가 **좌표의 유일한 출처**다. SVG 도 검증용 PNG 도 거기서
나온다. SVG 를 손으로 고치면 다음 실행에 덮인다.

## 격자 — 48 단위

48 = 16 × 3 이라 좌표가 3의 배수면 **16px 에서 모든 모서리가 정수 픽셀에
떨어진다.** 파비콘이 뭉개지지 않는 이유가 이것이고, 그래서 좌표를 눈으로
정하지 않는다. 16의 배수가 아닌 크기(180·120·167 …)는 4배로 그린 뒤 줄인다.

## 두 벌은 중심선을 공유한다

계단은 사각형 목록이 아니라 **중심선**(`STAIR_PATH`)으로 적고, 두께를 인자로
받는다. 작은 판이 큰 판의 **축약**이라는 사실이 파일이 아니라 코드에서
보장된다. 두께를 달리하는 것은 광학이다 — 작은 판은 굵혀야 16px 에서
살아남고, 큰 판은 가늘어야 판면이 검은 덩어리가 되지 않는다.

## 화면의 마크는 다트가 따로 그린다

앱 헤더는 `annals.dart` 의 `LogoMark` 가 그린다(`flutter_svg` 를 안 쓴다).
**PNG 한 장으로는 두 판을 못 맞추기 때문이다** — 한지 바탕에 맞춘 먹빛
마크는 먹빛 판면에서 사라지고, 바탕을 깔면 어두운 헤더에 흰 딱지가 붙는다.
좌표가 두 곳(파이썬·다트)에 있는 것은 알고 있다. 로고를 고치면 둘 다
고칠 것 — `widget_test.dart` 의 '로고 표장' 이 다크 대응을 지킨다.

## 아직 안 한 것

`app/web/og-image.png` 는 **옛 남색 로고 그대로다.** 공유 링크에 가장 많이
노출되는 자리인데 카드 디자인 전체가 옛 브랜드라, 아이콘처럼 기계로 바꿀
수 없고 다시 짜야 한다.

## 어떻게 여기까지 왔나

시안 네 회차의 판정과 실패가 `app/assets/brand/drafts/README.md` 에 있다.
'계선을 굵히면 판면이 막대그래프가 된다' 같은 것은 다시 만들 때 또 만난다.
