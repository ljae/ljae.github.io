# 분류 위키 — 스키마

이 디렉터리는 **학원 분류 지식의 위키**다. 구조는 karpathy 의 LLM wiki
패턴(원자료 / 위키 / 스키마 3계층)을 따른다.

- **원자료(불변)**: NEIS 원본(`pipeline/.cache/neis_raw.json`), 네이버 언급
  캐시(`naver_mentions.json`), Supabase 의 판정(`mention_reviews`)과
  규칙(`crawl_rules`). 위키는 이것들을 **읽기만** 한다.
- **위키(이 디렉터리)**: 학원 엔티티 페이지와 분류 개념 페이지.
  파이프라인이 매 실행 기계적으로 갱신하는 부분과, 사람/LLM 이 판단으로
  쓰는 산문이 한 파일에 공존한다.
- **스키마(이 문서)**: 페이지 규약과 성장 절차. LLM 세션(Claude Code)이
  위키를 손볼 때 이 문서가 지침이다.

## 페이지 종류

```
index.md            전체 목록 (전부 자동 생성 — 손대지 말 것)
log.md              실행 일지 (자동 append — 손대지 말 것)
concepts/*.md       분류 개념·함정. 사람/LLM 이 쓴다. CLAUDE.md 의 교훈 중
                    '글을 학원에 붙이는 일' 에 관한 것의 상세판.
academies/<id>.md   학원 엔티티 페이지. id 는 NEIS 학원지정번호.
cases/<id>.md       사례 페이지. 웹·대화로 받은 신고 한 건. 아래 '사례 노드' 참고.
```

## 학원 페이지 구조

```markdown
---
id: "22162"                # 필수. 파일명과 같아야 한다
name: 시매쓰학원            # 참고용 (등록명이 바뀌면 엔진이 경고)
region: banpo              # 참고용
# ↓ 엔진이 실제로 읽는 필드. 없으면 그 힌트는 없음.
aliases: [PEAI]            # 검색·매칭에 추가할 표기 (영문 약칭, 옛 이름…)
generic: true              # 이름이 일상어 → 학원 표지 요구를 강제
exclude_title: [뮤지컬]     # 제목에 있으면 이 학원 글이 아님
exclude_any: []            # 제목+본문 어디든 있으면 제외
unusable: true             # 이 이름으론 근거를 못 모은다 → 표본 0(점수·등수 없음)
locality: [방배]           # 같은 학군 형제 지점을 가를 동네 말
---
# 시매쓰학원 (서초 방배점)

(산문: 이 학원을 분류할 때 알아야 할 것. 근거 링크·실측 수치와 함께.)

## 판정 이력
<!-- auto:review -->
(자동 — 손대지 말 것)
<!-- /auto:review -->

## 통계
<!-- auto:stats -->
(자동 — 손대지 말 것)
<!-- /auto:stats -->
```

## 규약

1. **`<!-- auto:* -->` 마커 안은 기계 영역이다.** 파이프라인이 통째로
   갈아끼운다. 산문은 마커 밖에만 쓴다. 반대로 파이프라인은 마커 밖을
   절대 건드리지 않는다.
2. **모든 산문 주장에는 근거를 단다.** 실측 수치, 판정, 원문 URL.
   근거 없는 문장은 다음 사람이 지울 수도 고칠 수도 없다.
3. **위키 힌트는 관리자 검수를 대체하지 않는다.** 최종 제외 권한은
   여전히 `crawl_rules` 와 판정(verdict)에 있다. 위키의 exclude 는
   같은 게이트 경로를 지나며 실행 로그에 건수가 찍힌다 — 조용한 제외는
   없다. Supabase 규칙과 겹치는 낱말을 위키에 중복으로 넣지 말 것.
   (규칙은 운영자가 화면에서 끄고 켤 수 있지만 위키 파일은 커밋이다.)
4. **id 가 키다.** 통합(dedupe)으로 id 가 흡수되면 엔진이 경고를 낸다.
   그때 페이지를 대표 id 로 옮기는 것은 사람/LLM 의 일이다.
5. 페이지는 **알게 된 것이 있을 때** 만든다. 등록부 5천 곳 전부의 빈
   껍데기를 만들지 않는다. 자동 생성 조건: 랭킹 진입, 또는 판정·규칙·
   재분류가 그 학원을 건드렸을 때.

## 성장 절차

**매 실행(자동)** — `wiki.update()`:
- 조건에 든 학원의 페이지가 없으면 골격을 만든다.
- auto 블록(통계·판정 이력)을 갈아끼운다.
- `log.md` 에 실행 한 줄을 남긴다. `index.md` 를 다시 만든다.
- 모순을 경고한다: 별칭이 다른 학원과 겹침, exclude 가 자기 이름을 침,
  frontmatter 의 name 이 등록명과 어긋남.

**LLM 세션(수동)** — 사람이 신고를 가져오면:
1. 해당 학원 페이지를 읽는다(없으면 이 스키마대로 만든다).
2. 원자료로 원인을 확인하고, 산문에 **근거와 함께** 기록한다.
3. 엔진이 처리할 수 있는 것이면 frontmatter 힌트로 굳힌다.
4. 같은 함정이 다른 학원에도 보이면 `concepts/` 페이지로 올린다.
5. 판정이 필요한 것이면 위키가 아니라 관리자 검수(`/admin`)로 보낸다.

## 함정 목록 (상세는 concepts/)

- [[동명이인]] — 학원명이 사람 이름과 같다 (윤도영)
- [[일상어-학원명]] — 이름 자체가 일상어다 (책읽기)
- [[지역어-학원명]] — 이름이 지역어·업종어뿐이라 구(句)와 같다 (대치학원·목동학원)
- [[나열형-비교글]] — 여러 학원을 늘어놓은 글이 한 곳에 붙는다 (지엘피→피아이)
- [[지점-구분]] — 브랜드 후기를 어느 지점에 붙일 것인가 (에이프릴, 시매쓰)
- [[관-통합]] — 한 학원이 여러 건물·등록으로 갈라져 있다 (씨앤씨)
- [[대표명-함정]] — 통합 대표명이 검색어가 되어 오염원이 된다 (책읽기)

# 글 노드 (posts/)

후기 한 건이 파일 한 장이다. 지금까지 후기는 41MB 짜리 JSON 안에만 있어
점수에는 쓰이는데 **가리킬 수가 없었다.** '저 글은 가짜다' 라는 말을 받아도
붙일 자리가 없었다.

```
posts/<url_hash>.md   글 엔티티 페이지. url_hash 는 원문 URL 의 해시.
```

## 그래프

    노드   글(posts/) · 학원(academies/)
    엣지   글 → 학원. 양쪽에서 같은 것을 적는다.
             글 쪽   auto:edges  — 이 글이 어느 학원에 왜 붙었나
             학원 쪽 auto:posts  — 이 학원의 근거 글은 무엇인가

한 글이 여러 학원에 걸린다(비교글·브랜드 공통). 한 학원에 여러 글이 걸린다.
어느 쪽에서 읽어도 그래프를 따라갈 수 있어야 한다.

## 페이지 구조

```markdown
---
url_hash: "2d666906b4daeb9b476ff9aedde4c644"
url: https://cafe.naver.com/...        # 원문. 요약은 원문을 대체하지 않는다
source: naver_cafe
title: ...
posted_at: 2025-03-11                  # 모르면 빈 값 (카페 API 는 날짜를 안 준다)
author_hash: ...
# ↓ 엔진이 읽는 판단 필드. **사람이 쓴다** — 엔진은 절대 덮어쓰지 않는다.
verdict:                               # confirmed | rejected | reclassified
reject_reason:                         # 동명이인 | 무관 | 광고 | 오래됨 | 중복 | 기타
reassign_to: []                        # 이 글의 진짜 주인 (학원 id)
stale_after:                           # 이 날짜가 지나면 근거에서 뺀다
---
# 제목

원문: <url>

## 요약
<!-- auto:digest -->   감성·신뢰도·과목·스팸 — 파이프라인이 이미 계산한 것
<!-- auto:summary -->  LLM 한 문단. **키가 있을 때만.** 점수에 쓰이지 않는다

## 이 글이 붙은 학원
<!-- auto:edges -->

## 검수
<!-- auto:review -->   Supabase 운영자 판정 기록 (frontmatter 에 중복하지 않는다)

(산문 — 이 글을 어떻게 읽어야 하는지)
```

## 무효화 — 이 구조의 존재 이유

`verdict: rejected` + `reject_reason` 을 적고 다시 돌리면 **그 글의 영향이
전부 사라진다.** 그 학원의 표본·평판뿐 아니라 **코호트 평균과 다른 학원의
등수까지** 다시 계산된다. 파이프라인이 매 실행 전부를 원자료에서 다시 짓기
때문이다 — 부분 삭제라면 '어디까지 지워야 하나'를 사람이 판단해야 하지만,
재빌드에는 판단할 것이 없다.

실측(회귀 테스트 `pipeline/tests/test_posts.py`): A1 의 후기 12건 중 6건을
반려하니 A1 은 표본 부족으로 랭킹에서 빠지고, **후기가 하나도 안 줄어든
A2 의 총점이 30.5 → 32.3 으로 움직였다.**

## 규약

1. **`verdict` 는 사유 없이 쓰지 않는다.** 사유 없는 반려는 엔진이 무시하고
   경고를 찍는다. 이유 모르는 규칙은 나중에 지우지도 못하고 남는다.
2. **반려와 재분류는 다르다.** 네 학원 비교글이 한 곳에만 붙는 일이 있다.
   반려만 하면 멀쩡한 글이 통째로 버려지고 '어느 학원 글인지' 라는 사람이
   아는 정보도 함께 사라진다. `reassign_to` 로 진짜 주인에게 준다.
3. **가짜와 낡음은 다른 상태다.** 3년 전 '대기 걸렸다' 는 거짓이 아니라
   지난 사실이다 → `verdict` 가 아니라 `stale_after`.
4. **auto 블록을 엔진이 되읽지 않는다.** 엔진이 쓴 것을 엔진이 근거로 삼으면
   한 번의 실수가 영원히 자기를 증명한다.
5. **요약은 점수에 쓰지 않는다.** auto:summary 는 사람이 목록을 훑는 도구다.
   LLM 문장이 산식에 흘러들면 그때부터 산식을 설명할 수 없다.
6. 페이지는 **관련성 게이트를 통과한 글**에만 생긴다. 수집분 전부(2.9만)가
   아니라 실제로 근거가 된 글(약 9.4천)이다.

## 공식 홈페이지 (academies/ 의 homepage)

NEIS 는 홈페이지 주소를 주지 않는다. 학원 페이지 frontmatter 의
`homepage:` 에 **사람이 적은 것만** 읽는다. 이름으로 검색해 맞히지 않는다 —
'지엘피'·'피아이' 처럼 이름이 겹치는 학원이 이미 많고, 남의 사이트를 그
학원 것이라고 적으면 그게 곧 오보다.

적혀 있으면 엔진이 **robots.txt 를 먼저 확인하고** 읽어 auto:official 을
채운다. 거부하면 읽지 않는다(도구를 바꿔 우회하지 않는다). **본문은 저장하지
않는다** — 남의 저작물이다. 남기는 것은 '무엇이 몇 개 있고 지난 확인 대비
얼마나 달라졌나' 라는 관찰과 출처 URL·확인 날짜뿐이다.

# 사례 노드 (cases/)

신고 한 건이 파일 한 장이다. `pipeline/edutree/cases.py` 가 접수를 옮기고,
Claude Code 의 `/triage-reports` 와 `.claude/agents/` 가 진단·조치·검증을 산문에
적는다. 운영 절차는 `docs/AGENTS.md`.

```
cases/<id>.md   id 는 접수 창구 접두(co·er·cd·ma) + 접수 id 앞 8자. 같은 접수는 한 번만.
```

## 페이지 구조

```markdown
---
id: er-1a2b3c4d
source: evidence_report        # correction | evidence_report | claim_dispute | manual
entity_type: academy           # academy | textbook
entity_key: "1000035161"
reason: other_academy          # 접수 화면의 사유 코드
# ↓ 상태 기계. 에이전트·사람이 바꾼다. 엔진은 요약·감사에만 읽는다.
status: open                   # open → triaged → fixed → verified → closed | declined
category:                      # relevance | branch | subject | merge | claim | score | coverage | data_lag | display | other
resolution: []                 # post | wiki | rule | code | fixture | data | none
fixture:                       # tests/cases/<id>.yaml
landed_in:                     # 화면이 바뀐 데이터 커밋 sha
---
## 신고      <!-- auto:report -->  접수 원문 (엔진)
## 진단      case-triage — 어느 층인가, 근거는 파일:줄·수치·URL
## 조치      gate-* — 무엇을 어느 층에 바꿨나, 같은 원인의 다른 학원, 픽스처
## 확인      pipeline-verifier — 테스트·--from-cache(캐시라고 적는다)·데이터 커밋
```

## 규약

1. `auto:report` 안은 엔진 영역. 나머지는 사람·에이전트가 **날짜와 함께 덧붙인다**
   (`cases.append_section`) — 진단이 바뀐 경위가 남아야 같은 신고가 다시 왔을 때
   어디서 틀렸는지 안다.
2. frontmatter 는 `cases.set_fields` 로 줄 단위로 고친다. 없는 상태·종류는 거부된다.
3. **`fixed` 이상인데 `resolution` 이 code·rule·wiki 를 품으면 픽스처가 있어야 한다.**
   `cases.audit()` 이 매 실행 경고한다.
4. `verified` 는 `landed_in`(야간 데이터 커밋)이 있어야 한다. 캐시 수치로 올리지 않는다.
5. 사람이 정할 것(규칙 판정·가중치·형제 지점 확인)은 `## 조치` 에 질문으로 적고
   `triaged` 에 둔다. 에이전트가 대신 정하지 않는다.
