# 대치1관정상어학원

**영어 학원이다.** 같은 브랜드의 `대치정상수학학원`(등록번호 11410,
영동대로 229)은 **다른 학원**이고 등록부에 따로 있다. 둘을 합치지 말 것.

## 이 학원에서 세 번 틀렸다 (신고 2026-08-29 · 2026-08-30)

신고 내용: "대치정상수학학원은 수학·영어를 결합했는데 이름이 수학학원이라
부적절하다 · 진입난이도 근거가 대부분 무관한 글이다 · '정상'은 일상어다."
셋 다 맞았고, 원인이 서로 다른 층에 있었다.

1. **별칭이 일상어였다.** 시드 별칭 `정상` 이 '어느 정도가 정상인지',
   '정상적인 면역기능' 같은 글을 근거로 끌어왔다. 지역을 안 밝힌 글은
   형제 지점 전부에 붙으므로 별칭 하나가 다섯 지점을 흔들었다
   (대치 76 · 서초 153 · 잠실 92 · 송파 122건).
   → `analyze.EVERYDAY_ALIASES` (커밋 e36d7f46)
2. **사건 낱말이 공백을 넘어 생겼다.** '과학적인 8**대 기**능성' →
   공백을 지우니 '대기' 가 되어 진입난이도 '대기·웨이팅' 근거가 됐다.
   → `claims._contiguous` (커밋 e36d7f46)
3. **★ 통합 자체가 틀렸다 — 이건 한 회차 늦게 고쳤다.**
   `dedupe._SUFFIX_STRONG` 이 `'수학학원'` 을 업종어로 알고 통째로 떼서,
   `대치정상수학학원` 과 `대치1관정상어학원` 의 hall_key 가 **둘 다
   `'대치정상'`** 이 됐다. 관 통합 조건이 성립해 영어 학원과 수학 학원이
   한 학원이 됐고, 영어 후기 330건이 '수학학원' 이라는 이름을 달았다.

   앞선 회차는 **대표명만** 바꿔(수학학원 → 어학원) 증상을 덮었다.
   신고의 핵심은 이름이 아니라 **결합**이었다.
   → 업종어만 뗀다. 과목은 두 학원을 가르는 정보다.

   고친 뒤 실측: 표본 330 → 90, 진입난이도 61.1 → 49.1,
   `대치정상수학학원`(11410)은 등록부에 수학 학원으로 따로 선다.

## 이 페이지가 알려 주고 있었다 — 다른 이름으로

빌드가 매 실행 이렇게 찍고 있었다:

    ! 위키: 1000035161: 위키 name '대치1관정상어학원' ≠ 등록명 '대치정상수학학원'

이 경고가 곧 '서로 다른 두 학원이 한 id 에 들어 있다' 는 증거였는데,
문구가 '페이지 이관 필요?' 계열이라 **장부 정리 문제로 읽혀** 여러 회차
동안 지나쳤다. 이름 불일치 경고는 통합 오류의 신호로 볼 것.
